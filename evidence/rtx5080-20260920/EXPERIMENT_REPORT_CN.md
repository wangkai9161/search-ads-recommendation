# 搜索广告与推荐实验审计报告

## 1. 审计结论

本轮重新检查了数据、切分、模型选择和多随机种子稳定性。原有三组结果不能全部直接采用：

| 实验 | 原结果问题 | 修正 | 当前判断 |
| --- | --- | --- | --- |
| Criteo CVR | `product_price` 几乎直接暴露标签，导致 AUC 接近 1 | 主协议排除价格、收入和转化延迟；保留价格单特征仅用于诊断 | 修正后合理，DeepFM AUC `0.777870 +/- 0.001254` |
| MovieLens | 用最终测试目标选择 epoch；序列模型每用户只构造一个训练样本 | 每用户按时间留出验证/测试目标；验证集选 epoch；用历史前缀构造序列样本 | 修正后合理，GRU4Rec Recall@20 `0.090979 +/- 0.002772` |
| LastFM | 用测试集选 epoch；单次随机留出不足以支持稳健结论 | 每个种子独立留出验证/测试目标，验证集选 epoch，报告 3 个种子 | 修正后合理，BPR-1 Recall@20 `0.081076 +/- 0.003935` |

因此，旧的 “Criteo DeepFM AUC 0.995+”“MovieLens SASRec 最优”“LastFM 长尾加权最优”均不再作为主结论。

## 2. 环境与数据类型

- 环境：Python 3.10.12、PyTorch 2.11.0+cu128、RTX 5080；训练最多使用两张共享 GPU。
- Criteo Sponsored Search：来自 [Criteo 官方发布页](https://ailab.criteo.com/criteo-sponsored-search-conversion-log-dataset/) 的点击级表格二分类数据，目标是 `P(Sale=1 | click context)`。共 `15,995,634` 行；训练/验证/测试分别为 `10,815,826 / 2,278,739 / 2,901,069` 行，正例率分别为 `11.2169% / 10.2828% / 9.8308%`。
- MovieLens-1M：带时间戳的显式评分数据。原始 `1,000,209` 条评分，经 `rating >= 3` 转为隐式正反馈并过滤不足 3 次正反馈的用户后，得到 `836,477` 条交互、`6,038` 个用户、`3,628` 个物品。
- HetRec LastFM 2K：无时间戳的用户-艺术家隐式反馈。过滤不足 3 个不同艺术家的用户后，得到 `92,824` 条交互、`1,883` 个用户、`17,626` 个艺术家。

数据文件大小与 SHA-256 见 `environment.json`。原始数据、缓存和 checkpoint 不进入 GitHub。

## 3. 实验步骤

### 3.1 Criteo CVR

1. 流式读取 6.4 GB TSV，按 `click_timestamp` 做 70%/15%/15% 时间切分。
2. 只用训练段估计数值特征均值和标准差；类别特征采用字段命名空间隔离的确定性哈希，0 号桶专用于缺失值。
3. 排除明确的转化后字段 `SalesAmountInEuro`、`time_delay_for_conversion`。
4. 检查候选特征和标签的条件分布。发现 `product_price` 在测试段中 90.85% 为 0，且非零价格样本的转化率为 100%，非转化样本的非零价格比例为 0%。因此将它从主协议排除。
5. 在 clean 特征上统一比较 LR、FM、Wide & Deep、DeepFM。统一使用 embedding 维度 16、学习率 0.001、batch size 65,536、最多 10 epoch。
6. 每轮在验证集计算 LogLoss，使用 patience=3 的 early stopping；以验证 LogLoss 最小为主、PR-AUC 和 AUC 为次选择 checkpoint，测试集只评估一次。
7. DeepFM clean 特征消融使用随机种子 41/42/43，报告总体均值和总体标准差。

### 3.2 MovieLens

1. 按用户、时间排序正反馈；每个用户最后一次作为测试目标，倒数第二次作为验证目标，更早交互作为训练历史。
2. Two-Tower 学习用户 ID 与物品 ID 表示；GRU4Rec 和 SASRec 从每个用户的历史前缀构造多个下一物品样本，每个种子最多采样 200,000 个训练前缀。
3. Popularity 作为非学习基线。所有模型在完整物品库检索，屏蔽训练和验证阶段已知正反馈。
4. 学习模型最多训练 10 epoch，仅按验证 Recall@20 选择 epoch，然后在最终测试目标上评估一次。
5. 使用种子 41/42/43，报告 Recall@20 与 NDCG@20 的均值和总体标准差。

### 3.3 LastFM

1. 原数据没有时间戳，因此不声称时间切分。每个种子对每个用户随机但可复现地留出两个不同艺术家，分别作为验证和测试目标。
2. 用 ID-only Two-Tower 对比 BCE/BPR、0/1/3/5 个负样本及长尾加权。
3. 每个配置最多训练 10 epoch，用验证 Recall@20 选 epoch；测试集只评估一次。
4. 在完整艺术家库检索并过滤训练历史，同时分别报告 warm、tail、cold target；cold target 不计入可学习的 warm Recall。

## 4. 模型特点

| 模型 | 主要特点 | 适用解释 |
| --- | --- | --- |
| LR | 线性、易校准、无显式高阶交互 | CVR 可解释基线 |
| FM | 二阶隐向量交互 | 稀疏类别交叉基线 |
| Wide & Deep | 线性记忆分支加 MLP 泛化分支 | 同时拟合低阶与非线性模式 |
| DeepFM | FM 二阶交互与 DNN 共享 embedding | 自动学习低阶和高阶特征交互 |
| Two-Tower | 用户塔和物品塔独立编码，便于全库向量检索 | 召回阶段，但用户 ID 塔不建模顺序 |
| GRU4Rec | 递归更新短期兴趣状态 | 适合中等长度、有顺序的行为序列 |
| SASRec | 自注意力建模不同历史位置的依赖 | 表达能力强，但对训练预算和正则更敏感 |
| BPR | 直接优化正物品高于负物品的相对次序 | 与 Top-K 排序目标更一致 |

## 5. 结果对比

### 5.1 Criteo clean 四模型（seed 42）

| 模型 | Test LogLoss | Test PR-AUC | Test AUC | Test ECE |
| --- | ---: | ---: | ---: | ---: |
| LR | 0.279342 | 0.268036 | 0.765749 | **0.005451** |
| FM | 0.278196 | 0.276872 | 0.770010 | 0.008619 |
| Wide & Deep | 0.315669 | 0.243251 | 0.740691 | 0.044198 |
| DeepFM | **0.274910** | **0.285382** | **0.779100** | 0.011312 |

DeepFM 在排序和 LogLoss 上最佳，但优势是适度的，而不是异常接近完美。LR 的 ECE 最低，说明简单模型仍有校准优势。Wide & Deep 在当前统一超参数下收敛慢且 ECE 偏高，不能仅凭模型复杂度假设它一定优于 LR/FM。

### 5.2 Criteo clean DeepFM 消融（3 seeds）

| 特征 | Test LogLoss | Test PR-AUC | Test AUC |
| --- | ---: | ---: | ---: |
| clean | 0.275297 +/- 0.000761 | 0.285394 +/- 0.000128 | **0.777870 +/- 0.001254** |
| clean_no_user_id | **0.274713 +/- 0.000570** | 0.288641 +/- 0.001203 | 0.777521 +/- 0.000649 |
| clean_no_product_id | 0.275063 +/- 0.000780 | 0.285660 +/- 0.001777 | 0.776302 +/- 0.001271 |
| clean_no_entity_ids | 0.274787 +/- 0.000716 | **0.290042 +/- 0.002098** | 0.776285 +/- 0.001836 |
| clean_coarse_context | 0.295249 +/- 0.000103 | 0.197438 +/- 0.000204 | 0.712745 +/- 0.000447 |

删除用户 ID 或用户+商品 ID 不会造成显著下降，说明 clean 主结果不是依靠高基数实体 ID 记忆。粗粒度上下文删除了 audience、brand、product、partner、user 等字段后明显下降，说明品牌、卖家或受众等上下文携带有效但非近确定性的转化信号。

价格诊断中，`price_only` 的 AUC 为 `0.965585 +/- 0.000259`；`time_only` 和 `click_history_only` 分别只有 `0.503971` 和 `0.518173`。这验证了旧高分主要由价格字段的数据构造伪影造成。

### 5.3 MovieLens 完整物品库检索（3 seeds）

| 模型 | Test Recall@20 | Test NDCG@20 | Val Recall@20 |
| --- | ---: | ---: | ---: |
| Two-Tower | 0.064591 +/- 0.002042 | 0.023828 +/- 0.000993 | 0.078503 +/- 0.001412 |
| Popularity | 0.067241 +/- 0.000000 | 0.024795 +/- 0.000000 | 0.078006 +/- 0.000000 |
| GRU4Rec | **0.090979 +/- 0.002772** | **0.033728 +/- 0.001643** | **0.096610 +/- 0.001895** |
| SASRec | 0.064646 +/- 0.006707 | 0.024493 +/- 0.002478 | 0.068566 +/- 0.003524 |

GRU4Rec 相对 Popularity 的 Recall@20 提升约 35.3%。它在三种子上均领先，结论稳定。Two-Tower 只使用用户 ID，忽略行为顺序，因此未超过热度基线。SASRec 的标准差最大；在 200k 前缀样本和 10 epoch 的预算下，自注意力模型尚未得到稳定优势，不能沿用旧的 “SASRec 最优” 结论。

### 5.4 LastFM Two-Tower（3 seeds）

| 配置 | Test Recall@20 | NDCG@20 | Coverage@20 | Warm Recall@20 | Tail Recall@20 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BCE, neg=0 | 0.010621 +/- 0.005328 | 0.003335 | 0.170071 | 0.012054 | 0 |
| BCE, neg=1 | 0.062489 +/- 0.003368 | 0.021801 | 0.052649 | 0.070863 | 0 |
| BCE, neg=3 | 0.056293 +/- 0.001890 | 0.021676 | 0.048130 | 0.063827 | 0 |
| BCE, neg=5 | 0.056293 +/- 0.003035 | 0.021314 | 0.055883 | 0.063836 | 0 |
| BPR, neg=1 | **0.081076 +/- 0.003935** | **0.033771** | 0.002629 | **0.091927** | 0 |
| BPR, neg=3 | 0.079306 +/- 0.002952 | 0.031748 | 0.002307 | 0.089922 | 0 |
| BPR, neg=5 | 0.079306 +/- 0.002754 | 0.031695 | 0.002477 | 0.089916 | 0 |

BPR-1 与 Top-K 相对排序目标一致，因此取得最高 Recall/NDCG；增加到 3 或 5 个负样本没有收益。长尾加权提高了 BCE 配置的稳定性和覆盖率，但 Tail Recall@20 仍为 0。每个种子的 cold target 比例约 11.6%-12.2%，ID-only 模型无法为训练中未出现的艺术家学习可靠 embedding，因此不能宣称解决冷启动或长尾问题。

## 6. 最终原因分析与边界

1. 原 CVR 高分不合理的根因不是 DeepFM 特别强，而是 `product_price` 的取值与标签近确定相关。删除该字段后，AUC 降至约 0.78，恢复了不同模型之间的正常差距。
2. MovieLens 原结论受测试集选 epoch 和训练样本不足影响。修正后 GRU4Rec 利用有序历史，明显超过 ID-only Two-Tower 与热度基线；SASRec 在当前预算下不稳定。
3. LastFM 原单次结果把随机留出噪声当成模型优势。三种子结果显示 BPR-1 最稳健；tail weighting 没有带来可验证的尾部命中。
4. 所有结果均为公开数据集离线实验，不代表线上 A/B lift、生产吞吐或真实广告收入提升。
5. Criteo 只有点击样本，当前任务是 post-click CVR，不是 CTR、CTCVR 或 ESMM 全链路任务。

机器可读结果分别见 `cvr-robust-summary.json`、`movielens-10epoch-summary.json` 和 `lastfm/summary.json`。
